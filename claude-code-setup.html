PART 01

클로드 코드 활용가이드(shanraisshan/claude-code-best-practice)

바이브 코딩에서 에이전틱 엔지니어링으로 — 커뮤니티가 정리한 shanraisshan/claude-code-best-practice 저장소 한국어 요약. 트렌딩 저장소 · 팁 83개 · 워크플로우 13종 · 개념 15+

1.01

저장소 소개

"따라 하는 튜토리얼"이 아니라, Claude Code를 구성하는 원자 단위(에이전트·커맨드·스킬·훅 등)를 정리한 참고서. 챗봇처럼 쓰지 말고 각 primitive를 배워 스스로의 워크플로우를 조립하라는 것이 저자의 강조점.

구성

핵심 개념 표 · 개발 워크플로우(Research→Plan→Execute→Review→Ship) · 크로스 모델 연동 · 스킬/에이전트 모음집 · 실전 팁 83개 · 영상 · 심화 리포트

1.02

사용법 7단계

저자가 제시한 이 저장소 최적 활용 7단계.

  1. 1튜토리얼이 아니라 참고서로 읽기.먼저 훑어보고, 실제 실행은 나중에.
  2. 2Claude를 챗봇처럼 쓰지 않기.에이전트·커맨드·스킬·훅이라는 원자 단위를 배워 나만의 워크플로우로 조합한다.
  3. 3/weather-orchestrator 커맨드를 직접 실행.커맨드→에이전트→스킬로 이어지는 전체 흐름을 체험하고, 이를 자신의 개발 워크플로우 템플릿으로 삼는다.
  4. 4작업 중 커스텀 훅(hook) 사운드에 귀 기울이기.별도의 claude-code-hooks 저장소에 구현체가 있고, Agent Teams 같은 패턴은 implementation/ 폴더에 있다.
  5. 5🔥 주목 기능 표에서 심화 주제와 구현체를 학습.예: Ralph Wiggum 셀프 이볼빙 루프는 클론해서 바로 볼 수 있는 완전한 예제 저장소.
  6. 6실전 팁 섹션을 내 프로젝트에 붙여넣고 Claude에게 리뷰 요청.특히 CLAUDE.md 구조 개선안을 물어본다. 모든 팁은 Claude 팀 또는 커뮤니티 출처.
  7. 7Reddit·유튜브 채널 구독으로 최신 동향 follow-up.'구독' 섹션에 커뮤니티/공식 채널 목록 정리.
1.03

핵심 개념 & 위치

Claude Code 구성 기능과 실제 설정/파일 위치 정리 — 실무에서 자주 손대는 항목 위주.

기능위치 / 명령설명

체크포인트자동(파일 편집 추적)더블 Esc 또는 /rewind로 실패한 시도 이전으로 되돌리기
세션--resume, --continue, /resume, /branch세션 재개·분기. 중요한 세션은 /rename으로 이름 부여

1.04

주목할 최신 기능

저장소가 "요즘 뜨는 것"으로 꼽은 기능 중 실무 사용법 관점 핵심만 선별.

Scheduled Tasks/loop · /schedule/loop는 로컬 반복(최대 수일), /schedule은 클라우드 기반 정기 실행
Dynamic Workflows/workflows · ultracode 키워드여러 서브에이전트를 스크립트로 오케스트레이션

Sandboxing/sandbox파일·네트워크 격리로 권한 프롬프트를 대폭(사내 기준 84%) 감소
1.05

오케스트레이션 패턴 (커맨드 → 에이전트 → 스킬)

저장소가 제시하는 대표 예제 워크플로우 구조 — 커맨드가 진입점, 에이전트가 실행, 스킬이 세부 지침을 점진적으로 제공.

업무지시(COMMAND)를 하면 누가(AGENT) 무엇을 수행(SKILL). SKILL을 COMMAND화 하여 유저가 직접 수행도 가능

C 커맨드
→
A 에이전트
→
S 스킬
실행 예시
$ claude
> /weather-orchestrator
1.06

실전 팁 하이라이트

전체 83개 팁 중 사용법 학습에 특히 유용한 항목을 카테고리별로 추려 번역 (대부분 Claude Code 제작자 Boris Cherny, Anthropic Thariq의 트윗/영상 출처)

플래닝 & 프롬프팅 Planning · Prompting

  • 항상 Plan 모드로 먼저 시작한다.
  • 최소 스펙만 던지고, Claude에게 AskUserQuestion 툴로 나를 인터뷰하게 한 뒤 새 세션에서 실행시킨다.
  • 어중간한 수정 뒤엔 "지금 알게 된 걸 다 반영해서 이 방식은 버리고 우아한 해법으로 다시 짜줘"라고 요청한다.
  • PRD는 DB→API→UI 순으로 수평 분할하지 말고, 레이어를 관통하는 수직 슬라이스(tracer bullet)로 쪼갠다.

컨텍스트 & 세션 관리 Context · Session

  • 1M 컨텍스트 모델도 30~40만 토큰을 넘으면 "컨텍스트 로트"가 시작된다 — 중요한 작업은 그 전에 정리.
  • 컨텍스트 40%부터 품질 저하 체감, 60% 넘기지 않는 것을 권장(경험자는 30% 기준으로 더 보수적으로).
  • 실패한 시도는 고치지 말고 더블 Esc / /rewind로 되돌린 뒤 배운 것을 반영해 다시 프롬프트한다.
  • 다시 필요없는 툴 출력(파일 읽기·grep 등)은 서브에이전트에 위임해 메인 컨텍스트를 깨끗하게 유지한다.
  • 새로운 작업은 새 세션에서 — 관련 작업만 컨텍스트를 이어간다.

CLAUDE.md & 규칙 관리

  • CLAUDE.md는 파일당 200줄 이하를 목표로 한다(휴먼레이어 사례는 60줄).
  • .claude/rules/*.md는 CLAUDE.md처럼 자동 로딩되며, paths: 프론트매터로 특정 파일 패턴에서만 지연 로딩할 수 있다.
  • 파일이 길어질수록 무시되는 규칙이 생기므로 <important if="..."> 태그로 감싸서 강조한다.
  • 모노레포는 상위/하위 폴더에 CLAUDE.md를 각각 두면 조상→자손 순으로 함께 로딩된다.
  • "테스트 돌려줘"라고 했을 때 처음부터 성공해야 한다 — 안 되면 CLAUDE.md에 빌드/테스트 명령이 빠진 것.

에이전트 · 커맨드 · 스킬 설계

  • 범용 QA·백엔드 에이전트보다는, 별도 컨텍스트를 가진 기능 특화 서브에이전트 + 스킬 조합이 낫다.
  • "서브에이전트 써줘"라고만 말해도 컴퓨트를 더 투입해 메인 컨텍스트를 깔끔하게 유지할 수 있다.
  • 하루에 한 번 이상 반복하는 작업은 스킬/커맨드로 만든다.
  • 스킬은 파일이 아니라 폴더다 — references/, scripts/, examples/ 하위 폴더로 점진적 공개를 구성한다.
  • 스킬마다 Gotchas(함정) 섹션을 두고, Claude가 실패했던 지점을 계속 누적 기록한다.
  • 스킬의 description은 요약문이 아니라 "언제 발동해야 하는가"를 알려주는 트리거 문구로 작성한다.
  • 스킬 안에서 Claude를 단계별로 통제하지 말고, 목표와 제약만 준다.

훅 & 워크플로우 자동화

  • PostToolUse 훅으로 코드 자동 포맷팅 — Claude가 90%를 잘 짜면 훅이 나머지 10%를 처리.
  • Stop 훅으로 턴이 끝날 때 "계속 진행" 또는 "작업 검증"을 넛지한다.
  • --dangerously-skip-permissions 대신 /permissions의 와일드카드(Bash(npm run *) 등) 또는 Auto Mode를 쓴다.
  • /sandbox로 파일·네트워크를 격리하면 권한 프롬프트가 크게 줄어든다.
  • 회원가입 흐름·결제 검증 같은 제품 검증용 스킬에는 investment 가치가 크다.

Git / PR 워크플로우

  • PR은 작게 유지한다 — 중앙값 118줄 정도가 리뷰·되돌리기에 유리하다.
  • 항상 스쿼시 머지로 리니어 히스토리를 유지해 revert/bisect를 쉽게 한다.
  • 작업이 끝나는 대로, 최소 시간당 한 번은 커밋한다.
  • /code-review로 멀티 에이전트 PR 분석을 돌려 머지 전 버그·보안 취약점을 잡는다.

디버깅 & 유틸리티

  • 막히면 스크린샷을 찍어 Claude에게 바로 공유하는 습관을 들인다.
  • Claude in Chrome / Playwright MCP / Chrome DevTools MCP로 브라우저 콘솔 로그를 직접 보게 한다.
  • 로그를 봐야 하는 터미널은 백그라운드 태스크로 실행시킨다.
  • 벡터DB 기반 RAG보다 agentic search(glob+grep)가 낫다 — 코드는 계속 바뀌고 권한 문제도 복잡하기 때문.
  • /doctor로 설치·인증·설정 문제를 진단한다.

PART 02

클로드 코드 유용한 기능(스킬,플러그인 등)

이 워크스페이스 Claude Code 세션에 추가 설치·구성한 플러그인·스킬을 설치 순서대로 기록.

2.01

Ponytail

plugin · v4.9.0 · user scope · github.com/dietrichgebert/ponytail

에이전트가 "게으른 시니어 개발자"처럼 판단하도록 유도하는 규칙 세트. 코드를 작성하기 전 "정말 필요한 최소 구현인가"를 단계적으로 점검하게 해 불필요한 코드·과도한 추상화를 줄인다. 검증·보안·접근성 관련 코드는 절대 생략 대상에서 제외한다.

설치
/plugin marketplace add DietrichGebert/ponytail
/plugin install ponytail@ponytail
  • 설치 후 새 Claude Code 세션부터 자동 적용 (별도 명령 불필요)
  • 적용 여부 확인: /plugin list에서 ponytail@ponytail이 enabled 상태인지 확인
  • 비활성화 /plugin disable ponytail · 완전 제거 /plugin uninstall ponytail@ponytail
2.02

claude-mem

plugin · marketplace · thedotmack · github.com/thedotmack/claude-mem

세션이 끝나도 사라지지 않는 장기 기억을 Claude Code에 붙여주는 플러그인. 작업 중 생긴 관찰 내용(observation)을 로컬 SQLite에 자동 저장하고, 다음 세션 시작 시 관련 맥락을 자동으로 주입한다. 과거에 같은 문제를 어떻게 풀었는지, 어떤 결정을 내렸는지를 별도 요청 없이 다시 떠올릴 수 있게 해준다.

자동 기록

  • 세션 종료 시 대화·작업 내용을 관찰 로그로 요약해 로컬 DB에 저장 (백그라운드 워커)

자동 주입

  • 새 세션 시작 시 관련 과거 기억을 컨텍스트에 자동으로 불러옴

검색/타임라인

3.02

전역함수(gfn_*) 레퍼런스 스킬

skill · project scope · .claude/skills

_extlib_/ExtPrototype/comm*.js(14개 파일)에 정의된 drp-ui 프로젝트 전용 전역함수 gfn_* 206개를, 실제 사용 빈도(src/·frame/·userobject/·lib/ 전수 조사, 총 65,413회 호출) 순으로 정리한 카탈로그 스킬. 이미 있는 공통 로직을 새로 만들지 않도록 재사용을 유도하고, 정확한 파라미터 순서·타입·리턴값을 확인시켜 API 문법 오류를 예방한다.

01 · 사용빈도 Top 30

  • gfn_searchArgAdd(11,049회), gfn_alert(9,513회), gfn_transaction(6,133회), gfn_isNull(6,127회) 등 가장 많이 쓰이는 함수부터 요약표로 정리

  • gfn_Transaction, gfn_Alert, gfn_SetRequiredCol 등 대소문자만 다른, 실제로는 존재하지 않는 호출이 코드베이스에서 다수(최대 19회) 발견되어 목록화

넥사크로 API 레퍼런스 스킬

3.04.02

날짜 범위 결정

"이번 주"를 코드가 직접 계산 — 매주 사람이 날짜를 셀 필요 없음. 토요일 실행 시 그 주 월요일을 역산.

scripts/week_range.js — 기준일의 요일에서 월요일까지 거리 계산
daysSinceMonday = (요일 + 6) % 7        // 월=0 … 일=6
monday = 오늘 - daysSinceMonday일
friday = monday + 4일

결과: 시트에 쓸 "8월 17일" 형식 문자열 + Slack 필터링용 Unix epoch 범위.

3.04.03

Slack 대화 수집

내가 쓴 메시지뿐 아니라 멘션된 메시지, 스레드 답글까지 확인 대상. 관건은 "어느 채널을 볼 것인가"의 사전 등록.

채널 목록은 왜 미리 등록해둬야 하나

연동된 Slack MCP 도구에는 검색(search)·DM 목록 조회 API 부재. 감시할 채널·DM ID를 config.json에 사전 등록, 그 목록만 매주 순회. 채널 ID는 Slack 우클릭 → 링크 복사 시 URL 안 C0XXXXXXX / D0XXXXXXX 형태로 확인.

config.json — 감시 대상 채널
{
  "slackChannels": {
    "public":  [ { "id": "C0BLC8YK2AX", "name": "프레임워크버전업" }, ... ],
    "private": [ { "id": "C0A7KEJHHAL", "name": null }, ... ],
    "dm":      [ { "id": "D081J4JH7DK", "name": null }, ... ]
  }
}

필터링

채널 히스토리가 크면 파일로 저장 — 아래 스크립트로 "내가 쓴 것 + 나를 멘션한 것"만 추출, 답글 확인 필요 스레드 목록도 함께 추출.

scripts/filter_msgs.js 사용 예
node filter_msgs.js <채널히스토리.txt> U07RJ472Q6Q <startEpoch> <endEpoch>
# 출력: 관련 메시지 목록 + "이 스레드는 답글 확인 필요" 목록

이모티콘 반응으로 완료 여부까지 잡기

메시지 텍스트만으로는 "요청함"과 "요청해서 완료됨" 구분 곤란. 반응(reaction) 하나 추가 확인으로 상태까지 파악 가능 — 반응 자체가 아니라 반응이 달린 메시지·스레드의 내용으로 업무 관련 여부를 먼저 판단, 승인/완료류 반응이면 해당 항목에 상태 표시 부여.

분류 기준 예시
업무 완료/확인류: white_check_mark, 완료, 반영완료, +1, 넷, o-kay, ok_hand, 감사_합니다 …
단순 감정 표현(제외): heart, joy, wave, eyes, scream, clapping-good-job, ㅋㅋㅋ …

이모지 종류만으로 기계적 분류 금지 — 맥락 애매 시 스레드를 열어 실제 완료 여부 확인 후 반영 결정. 이렇게 잡은 항목은 보고서 문장 끝에 완료 한 마디로 충분.

3.04.04

Git 커밋 · 파일 집계

모듈별 리포지토리를 git log로 훑어 커밋 건수 + 건드린 파일 건수(중복 누적) 집계. 숫자만으로는 작업 내용 파악 곤란 — 원본 커밋 메시지를 모듈별로 모아 한 줄 요약(commitSummary)까지 함께 생성.

모듈별 반복 실행
git log --all --no-merges --author="이승일|lseungil" -E \
  --after="2026-08-24" --before="2026-08-29" \
  --pretty=format:"%h %ad %s" --date=short

# 수정 파일건수(중복 누적)
git log --all --no-merges --author="이승일|lseungil" -E \
  --after="2026-08-24" --before="2026-08-29" \
  --name-only --pretty=format: | grep -c .
플래그역할
--all체크아웃된 브랜치 1개만이 아니라 로컬의 모든 브랜치를 훑음
-E + |여러 작성자 표기(실명/영문 ID)를 정규식 alternation으로 한 번에
--no-mergesmerge 커밋 제외
--name-only커밋별 변경 파일명을 줄 단위로 출력 → 줄 수 = 파일건수

3.04.06

구글시트에 저장

Claude가 시트를 직접 여는 대신, 시트에 붙인 Apps Script 웹앱에 JSON을 POST 전송하는 방식. 시트 권한 이전 없이 어느 환경에서든 curl 한 번으로 저장 가능.

한 번은 꼭 이렇게 보내야 한다 — 파일 기반 UTF-8 전송
curl -s -L "<웹앱 URL>" \
  -H "Content-Type: application/json; charset=utf-8" \
  --data-binary @"payload.json"

-d로 한글 문자열을 명령줄에 직접 입력 시 터미널 인코딩 문제로 시트에 깨진 글자 유입. 반드시 파일로 작성 후 --data-binary로 전송.

3.04.07

실전에서 걸렸던 함정들

아래는 전부 실제로 한 번씩 걸려 고친 것들 — 비슷한 자동화 구축 시 같은 지점에서 시간 낭비 방지용 사전 참고.

01클라우드 스케줄러(routine)로는 못 돌린다

완전 자동화를 위해 클라우드 routine 시도 — routine은 격리된 클라우드 샌드박스에서 실행돼 사내망 GitLab·로컬 Slack MCP·로컬 스킬 파일에 접근 불가.

결론: 이 파이프라인은 로컬 PC 전용. 완전 자동화하려면 Windows 작업 스케줄러로 로컬 Claude Code CLI 예약 실행 필요 — 그마저도 해당 시간 PC 전원 필수. 현재는 매주 사람이 "돌려줘"라고 지시하는 방식으로 운영.

02git --author 정규식에 \|를 쓰면 조용히 실패한다

--author="이름\|lseungil"는 매칭 전혀 안 됨. -E(확장 정규식) 사용 시 백슬래시 없이 --author="이름|lseungil"로 작성 필수.

03체크아웃된 브랜치만 보면 커밋을 놓친다

모듈마다 현재 체크아웃된 브랜치가 매번 다름(develop / deploy / feature 브랜치 등). --all 없이 git log 실행 시 그 순간 체크아웃된 브랜치의 커밋만 노출. --all은 워킹트리 변경 없이 로컬 전체 브랜치를 훑어 이 문제 해소.

04구글시트 셀이 =로 시작하면 수식으로 오해한다

보고서 틀이 ====...==== 줄로 시작하는데, Apps Script setValue()는 셀 서식과 무관하게 = 시작 문자열을 무조건 수식으로 해석 — #ERROR! 발생.

서식 지정(setNumberFormat('@'))으로는 방지 불가. 값 앞에 폭 없는 공백(zero-width space) 삽입 필요 — 소스 코드에 문자 직접 붙여넣으면 인코딩 문제로 재손상 가능, String.fromCharCode(8203)처럼 코드로 생성해 삽입.

05새 행을 insertRowAfter로 만들면 서식이 깨진다

시트에는 체크박스·흰 배경 적용된 빈 행이 연말까지 미리 준비된 상태. insertRowAfter로 새 행 삽입 시 기준 행(헤더, 초록색·체크박스 없음)의 서식을 그대로 상속 — 행 색 초록색 전환, 체크박스 소실 문제 발생.

해결: 새 행 생성 대신, 준비된 빈 템플릿 행을 찾아 값만 채워 넣기.

06Apps Script 코드만 저장하면 배포된 웹앱엔 반영되지 않는다

/exec URL은 특정 배포 버전에 고정 — 코드 저장(Ctrl+S)만으로는 미반영, 배포 관리 → 편집 → 버전: 새 버전 → 배포 재실행 필수. 수정 후 매번 이 단계 확인 필요.

07Bash의 자동 분류기가 외부 웹훅 POST를 차단할 수 있다

curl로 Apps Script 웹훅 데이터 전송 시 "위험한 외부 전송"으로 분류돼 차단 가능. 동일 요청을 PowerShell Invoke-WebRequest -InFile로 전송 시 통과하는 경우 존재 — 한쪽 차단 시 다른 셸로 재시도.

  3. 3본인 Slack 채널·DM ID 수집감시하고 싶은 채널/DM에서 링크 복사 → ID 추출 → config.json에 등록
  4. 4Git 모듈 목록·작성자 패턴 지정본인이 커밋하는 리포지토리 경로와, 실명/영문ID를 담은 author 정규식 등록
  5. 5Claude Code에게 스킬 세팅 요청"이 가이드처럼 내 주간보고 자동화 스킬 만들어줘" 하고 본인 정보 알려주기

3.05

drp-screen-tester 에이전트

agent · Chrome 브라우저 제어 · .claude/agents

DRP 화면(프로그램ID)에 대한 QA 테스트를 전문으로 수행하는 서브에이전트. claude in Chrome을 활용. 브라우저로 실제 화면을 조작해 필수값·콤보박스·조회·저장 동작을 검증하고, 대응하는 백엔드 컨트롤러/매퍼/xfdl 코드까지 교차 확인한 뒤 Artifact HTML 리포트로 결과를 발행한다. 특정 화면에 종속되지 않는 범용 설계 — 프로그램ID 하나만 입력하면 동일한 절차로 어떤 화면이든 테스트할 수 있다.

트리거: "SESH0010 테스트해줘", "매장등록 화면 QA 해줘", "이 프로그램 검증해줘" 같은 요청에 사용.

01 · 테스트 절차

  • 화면 열기 → 필수값 미입력 저장 시도 → 콤보박스 옵션 확인 → 조회조건 검증 → 저장/응답 확인 순으로 실제 브라우저 조작

02 · 코드 교차검증

  • 화면에서 관찰된 동작을 대응 컨트롤러·매퍼(XML)·xfdl 스크립트와 대조해, UI 동작과 실제 백엔드 로직의 불일치를 잡아냄

03 · 리포트 발행

  • 검증 결과를 Artifact HTML 리포트로 발행 — 항목별 Pass/Fail과 근거를 한 페이지로 공유 가능

04 · 적용 원칙

  • 범용(프로그램ID 입력) + Artifact HTML 리포트 + UI/코드 교차검증을 기본값으로 설계 — 화면별 전용 스크립트를 매번 새로 만들지 않음

Chrome 자동화 도구(tabs/navigate/computer/read_page 등)로 화면을 직접 조작 · Read/Grep/Glob으로 소스 교차확인 · Artifact로 결과 발행

3.06

nexacro-guide 에이전트

agent · 읽기 전용 조사 · .claude/agents

NexacroN 24 컴포넌트/속성/이벤트/메서드 사용법을 조사할 때 쓰는 경량 조사 전용 서브에이전트. MCP 넥사크로 서버(mcp__nexacro__*)의 응답 지연 문제를 우회해, 로컬 레퍼런스 파일을 Read/Grep/Glob만으로 직접 검색해 답한다.

트리거: "그리드에서 행 추가하려면", "Dataset의 addRow 파라미터", "oncellclick 이벤트 언제 발생하나", ".xfdl에서 특정 컴포넌트 속성이 뭐가 있나" 같은 넥사크로 UI 개발 질문에 사용. drp-ui/pos-ui/scm-ui 작업 중 API 확인이 필요할 때 적극 활용.

01 · 조사 범위

  • 컴포넌트별 속성/이벤트/메서드, Dataset API 파라미터·리턴값, 이벤트 발생 시점 등 넥사크로 24 API 전반

02 · 도구 제한

  • Read / Grep / Glob만 사용 — 코드 수정 권한이 없는 순수 조사·질의응답 전용 에이전트

03 · 역할 분리

  • 넥사크로 API 레퍼런스 스킬(3.03절, nexacro-manual)을 primary source로 로드해 사용 — 넥사크로 플랫폼 자체 API(컴포넌트/속성/이벤트)만 다루며, drp-ui 전역함수 레퍼런스 스킬(3.02절, 프로젝트 자체 gfn_* 공통함수)과는 참조 대상이 다름
  • 이 에이전트는 drp-ui-global-functions 스킬을 직접 호출하지 않음 — 프로젝트 사용례 교차확인 시에도 GFN_REFERENCE.md가 아닌 commGrid.js/commTran.js 원본을 직접 grep

04 · 적용 원칙

  • 느린 MCP 서버 응답 대신 로컬 문서 검색으로 즉시 답변 — drp-ui/pos-ui/scm-ui 어느 모듈에서든 재사용

MCP_NEXACRO 서버 응답 지연 문제를 계기로, 로컬 md 레퍼런스 기반 조사 전용 에이전트로 생성
